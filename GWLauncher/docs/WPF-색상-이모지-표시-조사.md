# WPF에서 색상 이모지(🔴🟢⚠ 등)가 안 나오는 이유와 대안

## 왜 색이 안 나오는가

1. **WPF는 컬러 폰트를 기본으로 켜지 않음**  
   UWP에는 `TextBlock.IsColorFontEnabled` 같은 속성이 있지만, **일반 WPF에는 해당 API가 없습니다.**  
   그래서 같은 Segoe UI Emoji 폰트를 써도, WPF에서는 흑백 글리프로만 그려질 수 있습니다.

2. **폰트 선택 우선순위**  
   WPF는 DirectWrite를 쓰는데, 폰트 폴백 시 **흑백 이모지 폰트(Segoe UI Symbol 등)**를 색상 폰트(Segoe UI Emoji)보다 먼저 쓸 수 있습니다.  
   그래서 이모지가 Segoe UI Emoji가 아니라 Segoe UI Symbol로 그려지면 항상 흑백입니다.

3. **렌더링 파이프라인**  
   색상 폰트를 그리려면 DirectWrite의 **컬러 폰트 레이어**가 켜져야 하는데, WPF 쪽에서는 이걸 켜는 옵션이 공개되어 있지 않습니다.

## 적용해 본 방법 (TbP4SyncNeedSync)

- **Sync 필요여부**를 보여주는 `TbP4SyncNeedSync` TextBox에  
  `FontFamily="Segoe UI Emoji"` 를 지정해 두었습니다.
- 이렇게 하면:
  - 이모지 글리프는 Segoe UI Emoji로 그릴 가능성이 높아지고,
  - 한글/영문은 이 폰트에 없으므로 시스템 기본 폰트로 폴백됩니다.
- **단**, WPF가 컬러 폰트를 그리지 않도록 되어 있으면 **여전히 흑백**으로 나올 수 있습니다.  
  Windows 10/11 + 최신 WPF 환경에서는 환경에 따라 색이 나오는 경우도 있습니다.

## 그래도 색이 안 나올 때 쓸 수 있는 방법

| 방법 | 설명 |
|------|------|
| **1. Emoji.Wpf 라이브러리** | NuGet `Emoji.Wpf`로 이모지를 **이미지**로 치환해 컬러로 표시. 별도 컨트롤 사용 필요. 흐릿함/성능 이슈 있을 수 있음. |
| **2. WebView2** | 상태 문구를 HTML로 만들어 WebView2에 띄우고, `font-family: Segoe UI Emoji` 등으로 컬러 이모지 표시. 가장 확실하지만 구조가 무거워짐. |
| **3. 이모지 대신 텍스트/기호** | 🔴🟢 대신 `●`(U+25CF) + 색상(`Foreground`/`Brush`)으로 표시하거나, `[주의]` `[정상]` 같은 텍스트로 대체. WPF에서 색 제어가 가장 쉽고 안정적. |
| **4. 작은 컬러 이미지** | 원/삼각형 등 작은 PNG 아이콘을 리소스로 두고, 텍스트 대신 또는 텍스트 옆에 표시. |

## 요약

- **원인**: WPF에는 “컬러 폰트 사용” 옵션이 없고, 폰트 폴백이 흑백 이모지 폰트를 우선할 수 있음.
- **우선 시도**: `TbP4SyncNeedSync`에 `FontFamily="Segoe UI Emoji"` 적용 (이미 적용됨). 빌드해서 확인.
- **색이 안 나오면**: 같은 의미를 **색상 텍스트**(● + Foreground)나 **작은 아이콘 이미지**로 바꾸는 방식이 WPF에서는 가장 확실하고 호환성도 좋습니다.
